Важно

Статья опирается на предыдущую статью про промисы. В ней мы написали класс MyPromise — его реализация используется и здесь. Если вы её не читали, рекомендую начать с неё.


Но сперва, конечно же, теория.

Теория: зачем объединять промисы

«Коллекция промисов» звучит пафосно, но на самом деле это просто группа (почему не массив — станет понятно ниже), элементами которой являются объекты класса Promise. Причём это могут быть и не промисы вовсе — обычные значения, которые JavaScript сам приведёт к промису.

Зачем объединять промисы в группы? Чаще всего — когда одна и та же операция запускается для нескольких задач, и за их результатами нужно следить как за единым целым. Простой пример: несколько сетевых запросов к API, которые должны уйти не друг за другом, а одновременно, а результаты должны обработаться вместе. Вот тут и приходят на помощь методы для работы с группой промисов.

Для этих целей и нужны методы Promise.all(), Promise.race(), Promise.allSettled() и Promise.any().

У них простой синтаксис:

snippet(1).js
1Promise.all(iterable);
2Promise.race(iterable);
3Promise.any(iterable);
4Promise.allSettled(iterable);

Все четыре метода:

  • принимают на вход итерирумый объект iterable

    Элементами этого объекта не обязательно должны быть промисы, это могут быть любые значения. Если значение не промис, JavaScript сам приведёт его к промису. Главное, чтобы сам объект был итерируемым. Подробнее о том, что такое итерируемые объекты и чем они отличаются от массивов — в разделе практики (Перейти).

  • возвращают один новый промис

    Состояние и результат этого промиса зависит от того, что произойдёт с iterable внутри каждого метода. Все они ждут выполнения, но все разного:

    • Promise.all() ждёт выполнения всех промисов

    • Promise.race() ждёт первый завершившийся промис

    • Promise.allSettled() ждёт, когда завершатся все промисы

    • Promise.any() ждёт первый успешно выполненный промис

Разберём каждый метод отдельно. Под заголовком с названием каждого метода вот так указано короткое, но ёмкое правило для быстрого запоминания, что именно он делает.

Метод Promise.all()

Всё или ничего

Promise.all() ждёт выполнения всех промисов. Если все переданные промисы выполнились успешно — результатом будет массив значений в исходном порядке:

snippet(2).js
1Promise.all([
2  Promise.resolve('Первый выполнился'),
3  Promise.resolve('Второй выполнился'),
4  Promise.resolve('Третий выполнился'),
5]).then((result) => console.log(result));
Console
['Первый выполнился', 'Второй выполнился', 'Третий выполнился']

Порядок результатов сохраняется, даже если промисы завершаются в разное время:

snippet(3).js
1const resolveWithDelay = (value, delay) => {
2  return new Promise((resolve) => setTimeout(() => resolve(value), delay));
3};
4
5Promise.all([
6  resolveWithDelay('Первый выполнился', 3000),
7  resolveWithDelay('Второй выполнился', 1000),
8  resolveWithDelay('Третий выполнился', 2000),
9]).then((result) => console.log(result));
Console
['Первый выполнился', 'Второй выполнился', 'Третий выполнился']

Если хотя бы один промис будет отклонён, результатом будет ошибка первого отклонённого промиса:

snippet(4).js
1const rejectWithDelay = (value, delay) => {
2  return new Promise((_, reject) =>
3    setTimeout(() => {
4      console.log(value, 'пошёл');
5      reject(value);
6    }, delay)
7  );
8};
9
10const resolveWithDelay = (value, delay) => {
11  return new Promise((resolve) =>
12    setTimeout(() => {
13      console.log(value, 'пошёл');
14      resolve(value);
15    }, delay)
16  );
17};
18
19Promise.all([
20  resolveWithDelay('Первый', 3000),
21  rejectWithDelay('Второй', 1000),
22  resolveWithDelay('Третий', 2000),
23])
24  .then((result) => console.log(`${result} выполнился`))
25  .catch((error) => console.error(`${error} упал`));
Console
Второй пошёл
Error: Второй упал
Третий пошёл
Первый пошёл

В случае, если один промис отклоняется, остальные промисы продолжают выполняться, а результаты их выполнения игнорируются:

snippet(5).js
1Promise.all([
2  Promise.reject("Первый"),
3  Promise.reject("Второй"),
4  Promise.reject("Третий"),
5])
6  .then((result) => console.log(`${result} выполнился`))
7  .catch((error) => console.error(`${error} упал`));
Console
Error: Первый упал

Метод MyPromise.race()

Кто первый встал, того и тапки

Promise.race() ждёт первый завершившийся промис, возвращает результат его выполнения:

snippet(6).js
1Promise.race([
2  new Promise((resolve) => setTimeout(() => resolve('Первый'), 3000)),
3  new Promise((resolve) => setTimeout(() => resolve('Второй'), 2000)),
4  new Promise((resolve) => setTimeout(() => resolve('Третий'), 1000)),
5]).then((result) => console.log(result));
Console
Третий

Без разницы как завершился этот промис — удачно или с ошибкой — результатом всегда будет результат выполнения этого промиса:

snippet(7).js
1Promise.race([
2  new Promise((resolve) => setTimeout(() => resolve('Успешный успех'), 5000)),
3  new Promise((_, reject) => setTimeout(() => reject('Ой-ой, ошибочка'), 1000)),
4]).catch((error) => console.error(error));
Console
Ой-ой, ошибочка

Остальные промисы, как и в случае с Promise.all(), продолжают выполняться, а результаты их игнорируются:

snippet(8).js
1const resolveWithDelay = (value, delay) => {
2  return new Promise((resolve) =>
3    setTimeout(() => {
4      console.log(value, 'пошёл');
5      resolve(value);
6    }, delay)
7  );
8};
9
10Promise.race([
11  resolveWithDelay('Первый', 3000),
12  resolveWithDelay('Второй', 1000),
13  resolveWithDelay('Третий', 2000),
14]).then((result) => console.log(`${result} победил`));
Console
Второй пошёл // Через 1 секунду
Второй победил
Третий пошёл // Через 2 секунды
Первый пошёл // Через 3 секунды

Метод Promise.allSettled()

Вместе и до конца

Promise.allSettled() самый терпеливый метод из всех: он никогда не отклоняется, а ждёт завершения абсолютно всех промисов.

Для каждого промиса он формирует объект со статусом:

  • { status: 'fulfilled', value: ... } для выполненных успешно промисов

  • { status: 'rejected', reason: ... } для отклонённых промисов

Результат — массив таких объектов:

snippet(9).js
1Promise.allSettled([
2  Promise.resolve('Раз'),
3  Promise.reject('Ой-ой, ошибочка'),
4  Promise.resolve('Два'),
5]).then((result) => console.log(result));
Console
[
  { status: 'fulfilled', value: 'Раз' },
  { status: 'rejected', reason: 'Ой-ой, ошибочка' },
  { status: 'fulfilled', value: 'Два' }
]

Promise.allSettled() никогда не отклоняется, даже когда отклоняются все промисы:

snippet(10).js
1Promise.allSettled([
2  Promise.reject('Ой-ой, ошибочка #1'),
3  Promise.reject('Ой-ой, ошибочка #2'),
4  Promise.reject('Ой-ой, ошибочка #3'),
5]).then((error) => console.log(error));
Console
[
  { status: 'rejected', reason: 'Ой-ой, ошибочка #1' }
  { status: 'rejected', reason: 'Ой-ой, ошибочка #2' }
  { status: 'rejected', reason: 'Ой-ой, ошибочка #3' }
]

Обратите внимание: у Promise.allSettled() для получения результатов используется только then, а не catch.

Дополнительная информация

AggregateError — это подкласс класс ошибки Error, который упаковывает несколько ошибок в одну.

Что нам важно знать про AggregateError:

  • Конструктор выглядит так:

    snippet(11).js
    1new AggregateError(errors, message)

    Здесь errors это итерируемый объект (массив, коллекция) с ошибками, а message — необязательно человекочитаемое описание.

    Например:

    snippet(12).js
    1const error1 = new Error('Ой-ой, ошибка');
2  const error2 = new Error('Ой-ой, другая ошибка');
3
4  const errors = new AggregateError([error1, error2], 'Ой-ой, тут две ошибки');

  • Есть свойство errors:

    Через это свойство можно получить список ошибок:

    snippet(13).js
    1try {
2    throw new AggregateError([
3      new Error('Ой-ой, ошибочка'),
4      new Error('Ой-ой, другая ошибочка'),
5    ]);
6  } catch (error) {
7    console.error(error.errors);
8  }
    Console
    [
    { Error: 'Ой-ой, ошибочка' }
    { Error: 'Ой-ой, другая ошибочка' }
]

  • Есть свойство message:

    Через это свойство можно получить, соответственно, человекочитаемое описание:

    snippet(14).js
    1try {
2    throw new AggregateError(
3      [new Error('Ой-ой, ошибочка'), new Error('Ой-ой, другая ошибочка')],
4      'Обе операции упали'
5    );
6  } catch (error) {
7    console.error(error.message);
8  }
    Console
    Обе операции упали

Практика: пишем свои методы

Воспользуемся кастомным классом MyPromise.

Если не понимаете, что за класс MyPromise — всё в порядке. Просто загляните в статью про промисы.

Добавим к нему 4 статических метода:

snippet(15).js
1class MyPromise {
2  // Здесь вся остальная логика:
3  // - конструктор
4  // - статические методы resolve и reject
5  // - методы then, catch и finally
6
7  static all(iterable) {
8    // Реализовать нативный Promise.all()
9  }
10
11  static race(iterable) {
12    // Реализовать нативный Promise.race()
13  }
14
15  static allSettled(iterable) {
16    // Реализовать нативный Promise.allSettled()
17  }
18
19  static any(iterable) {
20    // Реализовать нативный Promise.any()
21  }
22}

Прежде чем переходить к написанию отдельных методов, определим, что их объединяет. Для этого посмотрим, что должны принимать и возвращать методы.

Все четыре метода устроены одинаково:

  • принимают итерируемый объект iterable

  • возвращают новый промис

Вопреки привычному порядку, начнём написание методов не с аргументов, а с возвращаемого значения.

Возвращаемое значение

Итак, в основе каждого метода лежит создание и возврат нового объекта Promise. Поэтому реализация каждого из методов будет начинаться со следующей конструкции:

snippet(16).js
1return new MyPromise((resolve, reject) => {
2   // Тут что-то делаем
3});

Теперь перенесём эту конструкцию в структуру каждого метода:

snippet(17).js
1class MyPromise {
2  static all(iterable) {
3    return new MyPromise((resolve, reject) => {
4       // Тут что-то делаем
5    });
6  }
7
8  static race(iterable) {
9    return new MyPromise((resolve, reject) => {
10       // Тут что-то делаем
11    });
12  }
13
14  static allSettled(iterable) {
15    return new MyPromise((resolve, reject) => {
16       // Тут что-то делаем
17    });
18  }
19
20  static any(iterable) {
21    return new MyPromise((resolve, reject) => {
22       // Тут что-то делаем
23    });
24  }
25}

С возвращаемым значением всё ясно, переходим к входным данным.

Входные данные

Каждый метод принимает на вход не массив, а итерируемый объект iterable. Любой массив является итерируемым объектом, но не наоборот. Разберёмся, в чём разница.

Представим, что мы добавили в каждый метод проверку через Array.isArray():

snippet(18).js
1static all(iterable) {
2  return new MyPromise((resolve, reject) => {
3    if (!Array.isArray(iterable) {
4      return reject(new TypeError('Argument must be array'));
5    }
6  });
7}

Это упрощённый пример — просто намеренно отклоняем всё, что не массив.

Тогда Set или строка вызовут ошибку:

snippet(19).js
1const set = new Set([1, 2, 3, 4, 5]);
2MyPromise.all(set).then((result) => console.log(result));
3
4const str = "Yay";
5MyPromise.all(str).then((result) => console.log(result));
Console
Ошибка: Argument must be array
Ошибка: Argument must be array

Казалось бы, логично. Но нативный Promise.all() спокойно принимает и Set, и строки — хотя они не массивы — и успешно выполняется:

snippet(20).js
1const set = new Set([1, 2, 3]);
2Promise.all(set).then((result) => console.log(result));
3
4const str = "Yay";
5Promise.all(str).then((result) => console.log(result));
Console
Array(3) [ 1, 2, 3 ]
Array(3) [ "Y", "a", "y" ]

Всё дело в том, что Set, Map и строки — итерируемые объекты.

Чем итерируемые объекты отличаются от массивов? Массив — это конкретный встроенный тип. А итерируемый объект —это любой объект, у которого реализован специальный протокол: есть метод с ключом Symbol.iterator, возвращающий итератор — объект с методом next(). Благодаря этому протоколу к итерируемым объектам применимы:

  • цикл for...of

  • оператор расширения ...spread

  • деструктуризация

  • конструкторы вроде Array.from(), new Map(), new Set()

Значит, Array.isArray() здесь не подходит. Зато теперь знаем, что у итерируемых объектов есть метод с ключом Symbol.iterator. Вот его и надо проверять — и делать это в самом начале: если передан не итерируемый объект, а проверки нет, дальше по коду что-то обязательно сломается.

Добавим такую проверку:

snippet(21).js
1if (typeof iterable[Symbol.iterator] !== 'function') {
2  return reject(new TypeError('Argument must be iterable'));
3}

Следует также отсечь null и undefined: без этого обращение к iterable[Symbol.iterator] выбросит ошибку прямо в момент проверки. Добавим дополнительную проверку на null и undefined:

snippet(22).js
1if (!iterable & typeof iterable[Symbol.iterator] !== 'function') {
2  return reject(new TypeError('Argument must be iterable'));
3}

Если условие истинно, значит, у объекта нет итератора — передавать его дальше нельзя. Эту проверку добавляем внутрь возвращаемого промиса к каждому методу:

snippet(23).js
1class MyPromise {
2  static all(iterable) {
3    return new MyPromise((resolve, reject) => {
4      if (!iterable || typeof iterable[Symbol.iterator] !== "function") {
5        return reject(new TypeError("Argument must be iterable"));
6      }
7    });
8  }
9
10  static race(iterable) {
11    return new MyPromise((resolve, reject) => {
12      if (!iterable || typeof iterable[Symbol.iterator] !== "function") {
13        return reject(new TypeError("Argument must be iterable"));
14      }
15    });
16  }
17
18  static allSettled(iterable) {
19    return new MyPromise((resolve, reject) => {
20      if (!iterable || typeof iterable[Symbol.iterator] !== "function") {
21        return reject(new TypeError("Argument must be iterable"));
22      }
23    });
24  }
25
26  static any(iterable) {
27    return new MyPromise((resolve, reject) => {
28      if (!iterable || typeof iterable[Symbol.iterator] !== "function") {
29        return reject(new TypeError("Argument must be iterable"));
30      }
31    });
32  }
33}

Помимо проверки итератора iterable, преобразуем итерируемый объект в массив — с ним удобнее работать:

snippet(24).js
1const items = Array.from(iterable);

Эта строка кода будет одинаковой для каждого метода:

iterable может быть Set, Map или другим итерируемым объектом.Array.from превращает его в массив, с которым просто работать: обращаться к элементам по индексу, вызывать методы перебора вроде forEach (спойлеры!).

Отдельно стоит рассмотреть случай, когда массив пуст. Для каждого метода он обрабатывается по-разному — этому посвящён следующий подраздел.

Краевые случаи

Пустой iterable

Все четыре метода принимают итерируемый объект и возвращают новый промис, но у каждого из них есть особое поведение при передаче пустого итерируемого объекта. Это тот случай, когда методы ведут себя по-разному — и именно это различие важно запомнить.

Promise.all([]) выполняется с пустым массивом []:

snippet(26).js
1Promise.all([]).then((result) => console.log(result));
Console
[]

Это логично: все промисы из пустого набора уже выполнены — их просто нет. Добавляем проверку: если массив пуст, сразу выполняем промис с пустым массивом:

snippet(27).js
1if (items.length === 0) {
2  return resolve([]);
3}

Это условие добавляем после приведения iterable к массиву:

snippet(28).js
1static all(iterable) {
2  return new MyPromise((resolve, reject) => {
3    if (!iterable || typeof iterable[Symbol.iterator] !== "function") {
4      return reject(new TypeError("Argument must be iterable"));
5    }
6
7    const items = Array.from(iterable);
8
9    if (items.length === 0) {
10      return resolve([]);
11    }
12  });
13}

Promise.race([]) навсегда остаётся в состоянии ожидания pending: никогда не выполняется и не отклоняется:

snippet(29).js
1const promise = Promise.race([])
2  .then((result) => console.log(result))
3  .catch((error) => console.error(error));
4
5console.log(promise);
Console
Promise { <state>: "pending" }

Никакого условия здесь в MyPromise.race() не добавляем.

Promise.allSettled([]) выполняется с пустым массивом []:

snippet(30).js
1Promise.allSettled([]).then((result) => console.log(result));
Console
[]

Как и в случае с Promise.all([]), метод просто сообщает: все промисы завершены, а раз их нет — завершать нечего. Добавляем такую же проверку как и у MyPromise.all():

snippet(31).js
1static all(iterable) {
2  return new MyPromise((resolve, reject) => {
3    if (!iterable || typeof iterable[Symbol.iterator] !== "function") {
4      return reject(new TypeError("Argument must be iterable"));
5    }
6
7    const items = Array.from(iterable);
8
9    if (items.length === 0) {
10      return resolve([]);
11    }
12  });
13}

Promise.any([]) отклоняется с ошибкой AggregateError:

snippet(32).js
1Promise.any([])
2  .then((result) => console.log(result))
3  .catch((error) => console.error(error));
Console
AggregateError: No Promise in Promise.any was resolved

Логика такая: метод ищет хотя бы один выполненный промис, но в пустом наборе такого нет — значит, ни один промис не выполнен, и это ошибка.

Добавляем в MyPromise.any() проверку: если массив пуст, отклоняем промис с AggregateError:

snippet(33).js
1if (items.length === 0) {
2  return reject(new AggregateError([], 'All promises were rejected'));
3}

Это условие добавляется после приведения iterable к массиву:

snippet(34).js
1static any(iterable) {
2  return new MyPromise((resolve, reject) => {
3    if (!iterable || typeof iterable[Symbol.iterator] !== "function") {
4      return reject(new TypeError("Argument must be iterable"));
5    }
6
7    const items = Array.from(iterable);
8
9    if (items.length === 0) {
10      return resolve([]);
11    }
12  });
13}

С входными и выходными данными разобрались. Теперь приступим к реализации каждого метода — начнём сPromise.all(). На его примере удобно разобрать основные приёмы, которые потом пригодятся и в остальных методах.

Метод MyPromise.all()

Всё или ничего

Promise.all() либо возвращает все результаты, либо отклоняется при первой же ошибке. Именно это и будем реализовывать. Разберём несколько примеров.

Promise.all() ждёт, пока выполнятся все переданные промисы, и возвращает массив их результатов в том же порядке, в котором они были переданы:

snippet(35).js
1Promise.all([
2  Promise.resolve('Первый выполнился'),
3  Promise.resolve('Второй выполнился'),
4  Promise.resolve('Второй выполнился'),
5]).then((result) => console.log(result));
Console
['Первый выполнился', 'Второй выполнился', 'Третий выполнился']

Порядок результатов сохраняется, даже если промисы завершаются в разное время:

snippet(36).js
1const resolveWithDelay = (value, delay) => {
2  return new Promise((resolve) => setTimeout(() => resolve(value), delay));

  1. промис

  2. не промис

Задача упростилась! Воспользуемся приёмом схлопывания промисов: если передать в Promise.resolve() промис, метод вернёт тот же самый промис, не создавая новый. Если передать не промис — будет создан уже выполненный промис с этим значением. Так все элементы в массиве будут сведены к одному типу — промису:

snippet(40).js
1items.forEach((item) => {
2  const promise = Promise.resolve(item);
3});

А с промисом что можно сделать? Вызвать у него методы then и catch:

snippet(41).js
1items.forEach((item, index) => {
2  MyPromise.resolve(item)
3    .then((value) => {
4      // Что-то сделать с результатом
5    })
6    .catch((error) => {
7      // Что-то сделать с ошибкой
8    });
9});

Такой перебор будем использовать во всех четырёх методах. Отличаться будет только содержимое then и catch.

Осталось понять, что нужно написать внутри этих колбэков здесь.

Начнём с простого — catch. Promise.all()) отклоняется, если хотя бы один из промисов отклонён, причём отклоняется с причиной первого отклонённого промиса. Поэтому если промис, который мы обрабатываем, отклоняется — сразу отклоняем и общий промис. Делается это добавление всего одной строки:

snippet(42).js
1items.forEach((item, index) => {
2  MyPromise.resolve(item)
3    .then((value) => {
4      // Что-то сделать с результатом
5    })
6    .catch((error) => {
7      reject(error);
8    });
9});

Обратите внимание

В нативном Promise.all() использует второй аргумент then — колбэк onRejected, а не catch:

snippet(43).js
1Promise.resolve(item).then(
2  (value) => {
3    // Что-то делается с результатом
4  },
5  (error) => {
6    // Что-то делается с ошибкой
7  }
8);

Если использовать catch после then, то он поймает ошибки и из самого промиса, и из then-колбэка. Для Promise.all() это не нужно — нужно поймать только отклонение исходного промиса.

Здесь оставим catch для наглядности: на результат это не влияет, но код читается чуть проще.

Заведём массив для результатов. Его длина должна равняться длине входящего массива — так мы сразу знаем, куда класть каждый результат:

snippet(44).js
1const results = new Array(items.length);

Если сохранять результаты через push, они будут добавляться в порядке завершения промисов, а не в порядке их передачи. Порядок сломается:

snippet(45).js
1.then((value) => {
2  results.push(value);
3})

А нам важен исходный порядок. Поэтому сохраняем результат по индексу:

snippet(46).js
1.then((value) => {
2  results[index] = value;
3})

Обратите внимание: index здесь — это позиция элемента во входном массиве. Именно по нему мы кладём результат, чтобы сохранить исходный порядок. Получаем этот индекс из forEach.

Результаты сохраняются, но нужно понять, когда все промисы выполнились. Нельзя просто сравнить длины results иitems: длина results равна items.length с самого начала — мы задали её при создании массива. Длина не говорит о том, заполнены ли элементы. А ещё длина массива в JavaScript — ненадёжный показатель: если записать элемент по индексу больше длины, массив растянется:

snippet(47).js
1const array = new Array(5);
2array[10] = 'Ой';
3
4console.log(array);
Console

В этом примере <10 empty slots> — пустые слоты. Это не undefined, а буквально дырки: массив знает свою длину, но элементов по этим индексам нет. Для нашей задачи это неважно — мы всегда заполняем все индексы. Но знать про эту разницу полезно.

Заведём отдельный счётчик завершённых промисов:

snippet(48).js
1let completedCount = 0;

Счётчик будет увеличиваться после каждого сохранения результата:

snippet(49).js
1results[index] = value;
2completedCount++;

Когда счётчик станет равен items.length, можно вызывать resolve(results):

snippet(50).js
1 if (completedCount === items.length) {
2  resolve(results);
3}

Собственно, это всё, что нужно сделать в then:

snippet(51).js
1.then((value) => {
2  results[index] = value;
3  completedCount++;
4
5  if (completedCount === items.length) {
6    resolve(results);
7  }
8})

Вот как выглядит MyPromise.all() целиком:

snippet(52).js
1static all(promises) {
2  return new MyPromise((resolve, reject) => {
3    if (!promises || typeof promises[Symbol.iterator] !== 'function') {
4      return reject(new TypeError('Argument must be iterable'));
5    }
6

8

10      return resolve([]);
11    }

Кто первый встал, того и тапки

Метод MyPromise.allSettled()

Вместе и до конца

MyPromise.allSettled() самый терпеливый метод из всех: он никогда не отклоняется, а ждёт завершения абсолютно всех промисов.

Для каждого промиса он формирует объект со статусом:

  • { status: 'fulfilled', value: ... } — если промис выполнился успешно

  • { status: 'rejected', reason: ... } — если промис был отклонён

Результат — массив таких объектов.

Возьмём скелет реализации:

snippet(70).js
1static allSettled(iterable) {
2    return new MyPromise((resolve, reject) => {
3      if (!iterable || typeof iterable[Symbol.iterator] !== 'function') {
4        return reject(new TypeError('Argument must be iterable'));
5      }
6
7      const items = Array.from(iterable);
8
9      if (items.length === 0) {
10        return resolve([]);
11      }
12    });
13  }

Promise.allSettled() — Promise.all(), который никогда не отклоняется: он так же ждёт завершения всех промисов, но не прерывается при первой ошибке, а собирает результаты всех и идёт до конца. Поэтому структура здесь будет такая же как и MyPromise.all(): понадобится массив и счётчик для промисов:

snippet(71).js
1const results = new Array(items.length);
2let completedCount = 0;

И снова пройдёмся по всем элементам:

snippet(72).js
1items.forEach((item, index) => {
2  MyPromise.resolve(item)
3    .then((value) => {
4      // Что-то сделать с результатом
5    })
6    .catch((error) => {
7      // Что-то сделать с ошибкой
8    });
9});

Колбэки в then и catch здесь будут, очевидно, отличаться. В then формируем объект для успешно выполненного промиса и сохраняем его по индексу:

snippet(73).js

1.catch((error) => {
2  results[index] = { status: 'rejected', reason: error };
3})

Затем нужно увеличить счётчик и проверить, равен ли он длине входящего массива:

snippet(75).js
1completedCount++;
2if (completedCount === items.length) resolve(results);

Этот код можно добавить и в then, и в catch — но тогда он продублируется:

Метод MyPromise.any()

Спасибо, что живой

Promise.any() возвращает результат первого успешно выполненного промиса:

snippet(84).js
1Promise.any([
2    Promise.resolve('Успешный успех #1'),
3    Promise.resolve('Успешный успех #2'),
4    Promise.resolve('Успешный успех #3'),
5  ]).then((result) => console.log(result));
Console
Успешный успех #1

Если все промисы отклонились, Promise.any() отклоняется со специальной ошибкой AggregateError:

snippet(85).js
1Promise.any([
2    Promise.reject('Ой-ой, ошибочка #1'),
3    Promise.reject('Ой-ой, ошибочка #2'),
4    Promise.reject('Ой-ой, ошибочка #3'),
5  ]).catch((error) => console.error(error.errors));
Console
[ 'Ой-ой, ошибочка #1', 'Ой-ой, ошибочка #2', 'Ой-ой, ошибочка #3' ]

Promise.any() — отзеркаленная версия Promise.all(). Если Promise.all() успешен только когда успешны все промисы, то Promise.any() успешен, когда успешен хотя бы один. И наоборот: Promise.all() отклоняется при первой ошибке, а Promise.any() — только если ошибочны все. Ошибки при этом собираются в том же порядке, в котором были переданы промисы. Это нам пригодится далее.

Возьмём скелет реализации:

snippet(86).js
1static any(iterable) {
2  return new MyPromise((resolve, reject) => {
3    if (!iterable || typeof iterable[Symbol.iterator] !== 'function') {
4      return reject(new TypeError('Argument must be iterable'));
5    }
6
7    const items = Array.from(iterable);
8
9    if (items.length === 0) {
10      return reject(new AggregateError([], 'All promises were rejected'));
11    }
12  });
13}

Раз нативный Promise.any() — отзеркаленная версия Promise.all(), заведём массив — но не для результатов, а для ошибок, —и счётчик отклонённых промисов:

snippet(87).js
1const errors = new Array(items.length);
2let rejectedCount = 0;

Как и в других методах, запускаем перебор:

snippet(88).js
1items.forEach((item, index) => {
2  MyPromise.resolve(item)
3    .then((value) => {
4      // Что-то делаем с результатом
5    })
6    .catch((error) => {
7      // Что-то делаем с ошибкой
8    });
9});

Осталось выяснить, что писать в колбэках.

Начнём с then. Нужно вернуть результат первого успешно выполненного промиса — это просто:

snippet(89).js
1.then((value) => {
2  resolve(value);
3})

Теперь catch. Логика здесь зеркальна MyPromise.all(): там мы сохраняли результаты в then, а здесь сохраняем ошибки — в catch. Записываем ошибку по индексу и увеличиваем счётчик:

snippet(90).js
1errors[index] = error;
2rejectedCount++;

Когда счётчик сравняется с количеством промисов, отклоняем общий промис с AggregateError, внутри которого — массив всех ошибок:

snippet(91).js
1if (rejectedCount === items.length) {
2  reject(new AggregateError(errors, 'All promises were rejected'));
3}

Получаем в итоге:

snippet(92).js
1if (rejectedCount === items.length) {
2  reject(new AggregateError(errors, 'All promises were rejected'));
3}

Всё!

Финальный метод будет выглядеть следующим образом:

snippet(93).js
1class MyPromise {
2  static any(iterable) {
3    return new MyPromise((resolve, reject) => {
4      if (!iterable || typeof iterable[Symbol.iterator] !== 'function') {
5        return reject(new TypeError('Argument must be iterable'));
6      }
7
8      const items = Array.from(iterable);
9
10      if (items.length === 0) {
11        return reject(new AggregateError([], 'All promises were rejected'));
12      }
13
14      const errors = new Array(items.length);
15      let rejectedCount = 0;
16
17      items.forEach((item, index) => {
18        MyPromise.resolve(item)
19          .then((value) => {
20            resolve(value);
21          })
22          .catch((error) => {
23            errors[index] = error;
24            rejectedCount++;
25
26            if (rejectedCount === items.length) {
27              reject(new AggregateError(errors, 'All promises were rejected'));
28            }
29          });
30      });
31    });
32  }
33}
